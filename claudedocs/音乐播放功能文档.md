# 音乐播放功能文档

## 📋 核心组件

### 1. **Esp32Music** (esp32_music.cc)
流式音频播放引擎

**核心功能**:
- MP3流式下载 + 解码播放
- 断点续传(2种方案)
- 双线程架构: 下载线程 + 播放线程

**关键方法**:
- `StartStreaming(url)` → 开始播放
- `StartStreamingFromPosition(url, position_ms)` → 方案A: 解码跳过
- `StartStreamingFromByteOffset(url, byte_offset)` → 方案B: HTTP Range
- `StopStreaming()` → 停止播放

**播放流程**:
```
下载线程: HTTP GET → 分块读取(4KB) → 缓冲区队列
           ↓
播放线程: 缓冲区 → MP3解码 → PCM数据 → Application音频队列
```

### 2. **MusicPlaylistManager** (music_playlist_manager.cc)
播放列表管理器

**功能**:
- 播放列表管理(增删查改)
- 播放模式: 顺序/随机/单曲循环
- 播放类型: 循环/单次
- 断点信息管理

**关键方法**:
- `SetPlaylist()` → 设置播放列表
- `GetNextItem()` → 自动下一曲(受模式限制)
- `ManualNext()/ManualPrevious()` → 手动切歌(无限制)
- `SaveCheckpointWithFrameInfo()` → 保存断点

**播放模式逻辑**:
```yaml
Single(单次): 播完当前歌停止
Loop(循环):
  - Sequential: 顺序循环
  - Random: 随机播放
  - SingleLoop: 单曲循环
```

### 3. **Application** (application.cc)
音乐控制协调层

**关键方法**:
- `HandleMusicCommand()` → 处理服务端指令
- `HandleMusicSetPlaylist()` → 设置播放列表(防抖)
- `HandleMusicControl()` → 播放控制(play/pause/next/prev)
- `OnMusicSongFinished()` → 歌曲结束回调
- `SendMusicStatus()` → 上报播放状态

**状态管理**:
```cpp
is_music_playing_    // 播放标志
is_switching_song_   // 切歌标志(防止状态切换到listening)
music_is_stopped_    // 停止标志(停止后不再上报状态)
music_status_timer_  // 30秒定时上报
```

## 🔄 核心流程

### 播放新歌曲
```
服务端 → {type:"music", action:"set_playlist"}
  ↓
Application::HandleMusicSetPlaylist()
  ↓ (防抖检查: 500ms)
  ↓ (同播放列表? → 仅切歌 : 完整设置)
  ↓
MusicPlaylistManager::SetPlaylist()
  ↓
Esp32Music::StartStreaming(url)
  ↓
设备状态 → kDeviceStateSpeaking
  ↓
开始上报状态(30秒/次)
```

### 暂停/恢复
```
暂停:
  music->StopSong() → 线程退出
  music->PauseSong() → 设置标志
  SaveCheckpointWithFrameInfo() → 保存断点(位置+字节偏移)
  SendMusicStatus() → 上报暂停状态

恢复:
  方案B优先: StartStreamingFromByteOffset() → HTTP Range快速恢复
  方案B失败: StartStreamingFromPosition() → 解码跳过恢复
  ClearCheckpoint() → 清除断点
```

### 自动切歌
```
歌曲播完 → Esp32Music回调
  ↓
Application::OnMusicSongFinished()
  ↓
MusicPlaylistManager::GetNextItem()
  ↓ (根据播放模式决定下一曲)
  ↓
Esp32Music::StartStreaming(next_url)
  ↓
music->SetAutomated(true) → 标记自动播放
```

## 🎯 关键逻辑点

### 1. 防抖机制 (application.cc:967-975)
```cpp
kSetPlaylistDebounceMs = 500ms
防止频繁调用导致设备崩溃
```

### 2. 同播放列表优化 (application.cc:1003-1044)
```cpp
if (is_same_playlist) {
  // 仅切换歌曲,不重新设置整个列表
  SetCurrentByItemId() → 直接切歌
}
```

### 3. 设备状态检查 (esp32_music.cc:676-697)
```cpp
播放线程检查: current_state != kDeviceStateSpeaking
  → Schedule切换到Speaking状态
  → 等待状态切换完成
  → 继续播放
```

### 4. 断点续传双方案
```cpp
方案B (快): HTTP Range请求从字节偏移开始
  优势: 无需解码,瞬间恢复
  要求: 服务器支持Range,有byte_offset信息

方案A (兼容): 从头下载但解码时跳过
  优势: 兼容性好
  劣势: 需解码丢弃数据,较慢
```

### 5. 状态上报控制 (application.cc:1287-1297)
```cpp
if (music_is_stopped_ && !force) {
  return; // 停止后不再上报,避免无效消息
}
```

## 📊 状态机

```
Idle → 收到播放指令
  ↓
Speaking (播放中)
  ↓
  ├─ 暂停 → Speaking (is_paused=true)
  ├─ 停止 → Listening (is_switching_song=true时不切换)
  └─ 播完 → Speaking (自动下一曲) / Listening (无下一曲)
```

## 🔧 线程架构

```
Main Event Loop (Core 0, Priority 3)
  ├─ HandleMusicCommand() → 处理指令
  ├─ OnMusicSongFinished() → 切歌回调
  └─ SendMusicStatus() → 定时上报

Download Thread (Priority 2, 8KB栈)
  └─ HTTP下载 → 缓冲区队列

Play Thread (Priority 2, 8KB栈)
  └─ 解码播放 → Application音频队列
```

## ⚠️ 注意事项

1. **线程安全**: 所有playlist操作都有mutex保护
2. **内存管理**: 音频数据使用SPIRAM分配
3. **状态同步**: is_switching_song_防止切歌时状态异常切换
4. **缓冲控制**: MIN_BUFFER_SIZE=64KB, MAX_BUFFER_SIZE=256KB
5. **防抖保护**: set_playlist操作500ms防抖

## 📡 协议接口

### 收: 音乐控制
```json
{
  "type": "music",
  "data": {
    "action": "set_playlist|play|pause|resume|stop|next|prev|set_mode",
    "playlist_id": 123,
    "items": [...],
    "play_mode": 0|1|2,  // Sequential|Random|SingleLoop
    "play_type": 0|1     // Loop|Single
  }
}
```

### 发: 播放状态
```json
{
  "type": "music_status",
  "data": {
    "playlist_id": 123,
    "item_id": 456,
    "resource_name": "歌曲名",
    "play_status": 0|1|2,  // 停止|播放|暂停
    "position": 30,         // 当前播放位置(秒)
    "play_mode": 0,
    "play_type": 0
  }
}
```
